# LCUI CPU 渲染基准设计

## 目标与范围

提供可重复运行的独立程序，测出现有软件渲染在典型负载下的成本，区分 UI 更新、脏区处理、光栅化与窗口提交，给出有实测依据的 CPU 优化优先级。首期实测 Windows x64 Release；通用离屏场景不创建原生窗口，不依赖 Win32 API 或第三方图形库。本期不修改生产渲染行为、不实现优化、不引入或评估第三方库。

## 程序与场景

在 `tests/benchmarks/` 增加非默认构建目标 `render-bench`。不注册为 `xmake test` 用例，也不设跨机器耗时阈值。CLI 可选择模式和场景，并设置预热帧数和采样帧数。无效参数、窗口初始化失败或校验失败返回非零，且不输出看似有效的结果。

| 模式 | 场景 | 用途 |
|---|---|---|
| `offscreen` | 不透明色块；同一批文字卡片分别配置普通、圆角、圆角加组透明度 | 用 `ui_init()` 初始化通用场景，通过基准专用原型在卡片上绘制 PandaGL 文字，再用 `ui_widget_render()` 绘制到复用的画布。窗口模式复用该场景。需要完整 LCUI 初始化的 Spinner 留在窗口模式。 |
| `window`（Windows） | 同样的色块与卡片；复用 `tests/scenes/spinner_perf_scene.c` | 创建原生窗口，驱动现有 LCUI UI Server 和 PTK 呈现。静态场景分别测无失效、单块小面积失效、同总输入面积的多块失效、整窗失效。Spinner 单独按固定角度步进，不使用实时动画计时器。 |

静态场景只标记绘制失效，不借助布局变更制造脏区。窗口先显示并完成初始化，测量期间保持客户区大小与 DPI 不变；尺寸变更或窗口被关闭时终止当前运行，避免混入不一致的帧。

## 计时与校验

- 采用单调高精度墙钟；Windows 用 `QueryPerformanceCounter`，POSIX 离屏路径用 `CLOCK_MONOTONIC`。场景构建、预热、窗口消息泵、节流等待、逐帧日志和像素校验不计入采样。窗口模式测的是应用侧从更新到提交的时间，不是桌面合成或显示器出帧时间。
- 离屏记录更新、清屏、widget 绘制和整帧。窗口记录动画推进（适用时）、UI 更新、UI Server 渲染、PTK 提交和整帧。整帧分位数直接从逐帧总耗时计算，不把各阶段分位数相加。
- UI Server 内部的脏区整理与实际绘制，用独立的诊断运行拆分；同时记录原始与实际绘制矩形数、实际绘制矩形面积总和，以及窗口上传字节量。面积总和允许重复计算重叠区域，不能当作唯一覆盖面积。内部观测只在基准诊断构建启用，不增加公共 API；诊断结果与正常计时分开报告。
- 输出模式、场景、构建类型、逻辑和像素尺寸、DPI、预热和样本数，以及各阶段的 p50/p95。固定场景用代表性像素验证背景、内容和裁剪；窗口模式检查应绘制的场景确有绘制工作，无失效对照不产生错误的重绘。检查本身不设耗时阈值。

## 归因与交付

1. 用 Windows Release 运行全套基线，记录运行命令和环境；以重复运行区分稳定差异与测量噪声。用短采样运行验证入口和输出，再用正常采样取得基线。若未在 POSIX 环境执行，单独注明离屏兼容性未实测。
2. 比较单块与多块的实际工作量，定位脏矩形重复遍历；比较普通、圆角和透明卡片，定位额外离屏分配与混合；比较静止和动画场景，区分动画自身成本和树绘制成本；比较不同失效面积，判断呈现拷贝是否固定。对关键差异用独立诊断计数或 CPU 采样调用栈佐证。
3. 报告包含基准命令、各场景数据、热点源码位置、证据局限和排序后的 CPU 优化候选。若耗时主要在窗口提交或 UI 更新，应如实报告，不将其归为 PandaGL 光栅化问题。缓冲复用、不透明快路径、脏区合并等是否优先，取决于采样结果；本期不落地这些改动。
